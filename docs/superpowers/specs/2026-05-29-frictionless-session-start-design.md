# Frictionless Session Start — Design

**Date:** 2026-05-29
**Branch:** experiment/parallel-questions
**Status:** Approved, pending implementation plan

## Problem

Starting a conversation has too much friction for stakeholders:

1. After logging in they face a blank screen and must figure out what to do.
2. To begin, they must click "New Session", type a project title, and submit a
   form before they can say anything.
3. The blank chat panel gives no cue that the AI is ready to help.

This makes the tool feel like work before any value appears. We want a
stakeholder to log in and immediately be able to talk.

## Goals

- The AI greets the stakeholder first, so the screen is never blank.
- No manual session-title typing — names are derived automatically.
- Logging in lands the stakeholder directly in a ready-to-talk state.
- No empty/junk sessions accumulate from logging in and leaving.

## Non-Goals

- Changing the SRE (requirements engineer) flow. SRE still lands on `/spec`.
- Renaming sessions after the first auto-name (one-shot naming only).
- LLM-generated greetings (the opener is a fixed string by decision).

## Decisions (from brainstorming)

- **AI opener:** fixed friendly greeting, not LLM-generated.
- **Auto-name:** short title generated by one LLM call from the first
  stakeholder message.
- **Session persistence timing:** draft — the session is written to the DB only
  when the stakeholder sends their first message, not on login.

## Shared Constant

The greeting text is used in two places and must match exactly:

> "Hi! I'm here to help capture what you'd like to build. What's the project or idea you have in mind?"

Backend defines it for the seeded turn; frontend defines it for the draft
bubble. Both render identical text so there is no flicker when a draft becomes a
persisted session.

## Feature 1 — AI Opens the Conversation

### Backend
- In `create_session` (`backend/app/routers/sessions.py`), after inserting the
  session document, insert a seed **agent turn**:
  - `role: "agent"`, `content: <GREETING>`, `created_at: now`.
  - No `strategy` field (so `ChatPanel` renders no strategy badge — it is a
    greeting, not a probing move).
  - Validator fields omitted.

### Frontend
- No new display logic for the persisted case: `LiveRequirements` already
  fetches turns when `activeId` changes, so the seeded greeting appears when the
  session opens.

## Feature 2 — Auto Session Name

### Backend
- `SessionCreate.project_title` (`backend/app/schemas/session.py`) becomes
  optional, defaulting to placeholder `"New conversation"`.
- `create_session` sets `auto_named: false` on the new session document.
- New service `backend/app/services/title_generator.py` — `TitleGenerator`,
  same shape as `RequirementExtractor`:
  - Constructor takes `llm`.
  - `async def generate(self, stakeholder_text: str) -> str` — one LLM call,
    returns a 2–5 word title. Strips quotes/trailing punctuation. Falls back to
    `"New conversation"` if the call returns empty.
- In `post_message` (`backend/app/routers/dialogue.py`): after the stakeholder
  turn is stored, if the session's `auto_named` is false:
  - Generate a title and update the session
    (`project_title` + `auto_named: true`).
  - Wrap in `try/except` — on failure keep the placeholder and `auto_named:
    false`; never block or fail the reply.
- Apply the same auto-name block to `post_turn` for symmetry.
- `MessageResponse` (`backend/app/schemas/dialogue.py`) gains
  `session_title: str | None = None`, returning the (possibly updated) title.

### Frontend
- `postMessage` return type (`frontend/src/api/sessions.ts`) gains
  `session_title?: string | null`.
- After the first `postMessage` succeeds, update the sidebar with the new title
  (refresh `listSessions()` into the store, or patch the active session's title
  in place).

## Feature 3 — Auto-Start on Login (Draft)

### Store
- `sessionStore` (`frontend/src/store/sessionStore.ts`) gains a `draft: boolean`
  flag and a `setDraft(v: boolean)` action.
- Entering draft mode sets `draft: true`, `activeId: null`, and clears
  `turns`/`requirements`.
- Selecting any real session sets `draft: false`.

### Landing
- On arriving at `/chat` (MainPage) with no active session, enable draft mode so
  the greeting shows immediately with zero clicks.

### Chat panel
- `ChatPanel` (`frontend/src/components/Dialogue/ChatPanel.tsx`): when `draft` is
  true and there are no turns, render the greeting as a static agent bubble
  (same styling as a normal agent turn, no badge).

### Input box
- `InputBox` (`frontend/src/components/Dialogue/InputBox.tsx`): render the input
  when `activeId` is set **or** `draft` is true (today it returns null without an
  `activeId`).
- `onSend` in draft mode:
  1. `createSession()` with no title (backend applies placeholder + seeds
     greeting).
  2. Set the new session active, leave draft mode.
  3. Proceed with the existing send flow (`postMessage` → refresh requirements →
     `postQuestion` loop) against the new session id.
- Optimistic rendering: the draft greeting bubble and the optimistic stakeholder
  bubble should carry over cleanly; once the new session's turns load from the
  DB (seeded greeting + stakeholder turn), they replace the client-side draft
  state without duplication.

### Sidebar
- `SessionList` (`frontend/src/components/Sidebar/SessionList.tsx`): the "New
  Session" button enters draft mode (`setDraft(true)`) instead of toggling a
  title form. Remove the title input form and its local `title`/`creating`
  state.
- `createSession` in `frontend/src/api/sessions.ts` becomes callable with no
  argument (posts an empty/placeholder body).

## Data Flow (happy path)

1. Stakeholder logs in → routed to `/chat` → draft mode on → greeting bubble
   visible.
2. Stakeholder types their idea and sends.
3. `InputBox` creates the session (placeholder title, backend seeds greeting
   agent turn), then posts the message.
4. Backend stores the stakeholder turn, sees `auto_named: false`, generates a
   title (e.g. "Calendar Task Sync"), updates the session, returns
   `session_title`.
5. Frontend updates the sidebar title; question loop runs as today.
6. Reopening the session later loads the seeded greeting + full history from the
   DB.

## Error Handling

- **Greeting seed insert fails:** session creation should still succeed; a
  missing greeting turn is cosmetic (the draft bubble already showed). Insert is
  best-effort.
- **Title generation fails / LLM unavailable:** caught; session keeps
  "New conversation" and `auto_named: false` (so a later message can retry).
  The reply is never blocked.
- **Session creation fails during draft send:** roll back the optimistic
  stakeholder bubble, restore the textbox, surface the error, stay in draft
  mode (mirrors the existing `postMessage` failure handling).

## Testing

- **Backend unit:** `create_session` inserts exactly one seed agent turn with the
  greeting and no strategy. `SessionCreate` accepts a missing title and applies
  the placeholder.
- **Backend unit:** `TitleGenerator.generate` returns a trimmed short title;
  returns the placeholder fallback on empty/garbage output.
- **Backend integration:** first `post_message` on a placeholder session sets
  `project_title` and `auto_named: true`; a second message does not rename;
  title-generation failure leaves the placeholder and does not error.
- **Frontend (manual / component):** landing on `/chat` shows the greeting with
  no active session; sending from draft creates and selects a session, renames
  the sidebar, and does not leave a stray empty session; logging in and leaving
  without sending creates no session.
